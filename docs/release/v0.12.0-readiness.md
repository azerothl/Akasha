# Préparation de la release Akasha 0.12.0

État relevé le 23 octobre 2026. Ce document prépare la publication ; aucun tag ni release n'a été créé.

## Version

- Cargo.toml, le client Tauri et ses fichiers npm sont synchronisés en 0.12.0 avec le script de synchronisation de version.
- La dernière release publique observée est v0.11.0.
- Le workflow Release publie lors du push d'un tag v*. Ne pousser le tag qu'après validation de cette checklist.

## Validations

- Les vérifications CPU de la pile #258/#259 (Rust, évaluations, tests et UI E2E) étaient vertes au relevé ; la CI du commit de cette PR doit également être verte.
- Le job GPU était encore en attente et la recette d'archive premier démarrage était ignorée en contexte PR ; cela ne constitue pas une validation CUDA ou d'archive. Les builds et vérifications d'archives de la release devront être consultés avant publication.
- Le parcours réel de création d'une Todo list dans Code Studio n'a pas livré une application validée. Le Kanban et une reprise automatique ont été observés, mais l'implémentation, ses tests et l'aperçu n'ont pas été achevés : [rapport du 23 octobre](https://github.com/azerothl/Akasha-code-studio/blob/codex/studio-timeout-recovery/docs/validation/inspection-handoff-vitest-real-2026-10-23.md).

## Ordre proposé

1. Valider et publier Akasha v0.12.0.
2. Publier ensuite Akasha Code Studio v0.10.0, qui utilise les API Studio de cette version du daemon.

La publication n'est pas prête tant que les validations CI et les builds de release ne sont pas vérifiés. Si la livraison autonome par vrai LLM est un critère de sortie, elle reste également bloquante.
